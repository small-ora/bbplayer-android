# SPEC — 主菜单迁到左上侧边栏 + 底栏改为音乐播放控件

状态：实现前冻结（本会话）。级别：**L2**（多文件 UI 重构 + 需要人验收视觉取舍；不涉鉴权/schema/依赖）。
基线：v4 `e71c9bd`；分支 `feat/ui-sidebar-playerbar`。
参照：椒盐音乐（Salt Player）底栏播放控件 + 汉堡开左侧菜单的交互模型。

## 1. 用户需求（原话）

> 把底部的菜单栏修改为右上角或者左上角的侧边栏。因为底栏需要放音乐的相关控件，就参考椒盐音乐的底栏音乐播放控件那些。

由此拍板（Lead 判断，人可否决）：

- 侧边栏选**左上角汉堡触发的左侧抽屉**（Salt Player 截图里汉堡在标题左侧；右抽屉记录为非目标，一行开关可切换）。
- 底栏=**纯音乐播放控件**（迷你播放条），不再含任何导航图标。
- 另一会话正在做登录体系，本任务的抽屉**不接入账号/登录 UI**（避免与其写范围冲突），账号入口后续合并时再挂到抽屉头部（记录为合并契约，见 §6）。

## 2. 目标

窄屏主界面：导航从底栏迁到左侧抽屉；底部只保留音乐播放控件（封面/标题/歌手/进度线/上一首/播放暂停/下一首/队列）。
宽屏保留左侧常驻导航栏；平板/横屏底部仍为播放条。

## 4. 非目标

- 不做登录/账号/收藏/合集等 v5 功能 UI，不改 `ProfileScreen`/`LibraryScreen`/`SettingsScreen`/`PlayerScreen`/`RealAppGraph`/`data/**`。
- 不新增依赖、不改主题 token、不改 `MiniPlayerStyle` 默认值。
- 不做全局悬浮播放条（详情页/设置页暂不显示，维持现状：仅主 tab 页）。
- 不做迷你条歌词行、左右滑切歌、上滑展开等手势（记录为后续可选）。
- 不做右侧抽屉（记录：`drawerState`/布局方向一处可切）。

## 5. 风险与人工门禁

- 视觉取舍（抽屉宽度、条目密度、播放条高度/控件顺序）需人验收；筛选按钮是否有队列按钮等以 AC2 为准，其余以截图为准。
- `ModalNavigationDrawer` 手势默认会拦截横向拖拽 → 关闭手势，仅按钮触发（记录）。
- 共享设备/构建资源（另一会话并行）→ 证据注明构建时间与 commit。

## 6. 合并契约（给另一会话/后续合并）

- 本分支新增 `ui/components/NavDrawer.kt`、`ui/components/BottomPlayerBar.kt`；修改 `ui/components/Headers.kt`、`ui/AppRoot.kt`；删除 `ui/components/BottomDock.kt`、`ui/components/MiniPlayer.kt`。

- `NavDrawer` 的账号头部是预留扩展点（注释 `// [MERGE-HOOK]`）：v5 登录落地后，在抽屉头部插入头像/昵称/登录入口即可，不影响本分支其余代码。
